Backend engineering, from first principles

Backend is enormous. Cover every component that could possibly be part of it and you will be here for years. So these notes deliberately cover only what turns up in the overwhelming majority of codebases — the 10% of backend that explains 90% of the code you will actually read.

Concepts before code. No framework, no language — the mechanisms underneath, which stay true whichever stack you end up in.

How these notes are organised

  • Lead Every lesson opens with a one-paragraph statement of what the topic actually is, before any detail.
  • Callouts Key boxes hold the idea worth memorising. Note adds context, Tip is practical advice, and Warn flags something that bites in production.
  • Flows Numbered sequences for anything with an order to it — the CORS preflight, the OIDC handshake, a login request.
  • Messages Annotated request and response blocks. The comments in the margin are the part to read.
  • Takeaways Each major part closes with a boxed summary. Revising? Read only these first, then go back into whatever felt shaky.
